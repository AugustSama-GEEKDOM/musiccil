# musiccil

一个终端里的**黑胶唱片机**播放器：封面主色驱动整套界面配色、唱片中心是一张跟着旋转的像素风封面、
歌词滚动、真实音频播放（mpv 后端）。同时提供一个原生 C++ 图形界面，用来搜歌和组歌单。

纯终端运行，没有网页。

## 接口服务（密钥与配额）

曲库数据来自聚合接口，客户端不带任何密钥，而是用**你自己的密钥**去调接口服务：

```
播放器 / GUI / 脚本
GET https://muscil.geekdom.top/open/music/url?key=你的密钥&id=4875127&type=wy
        ↓
    校验密钥 → 计算配额 → 返回数据（路径、参数、响应三者与接口文档完全一致）
```

密钥在站点上免费领取：注册账号 → 自动生成密钥 → 面板里复制 → `musiccil --setup` 保存。
站点同时提供这些能力：

- **账号系统**：邮箱验证码注册、登录、改密码
- **密钥管理**：每个账号最多 10 把，可重置、可停用
- **配额**：调用一次扣一次。新账号有初始配额，每天首次调用自动补一份，还能靠签到和兑换码补
- **用量面板**：剩余配额、今日/近 14 天用量、按接口分布、最近调用明细

取数失败时**退还**这一次的配额；校验密钥的 `/api/key-info` 不扣配额。

| 你有 / 你想 | 去哪 |
|---|---|
| 只想听歌 | [muscil.geekdom.top](https://muscil.geekdom.top) 注册领密钥，剩下的都在播放器里 |
| 换一个接口地址 | `set MUSICCIL_API_BASE=https://你的地址/open/music/` |

## 两种用法

同一个播放内核，两个入口：

| 入口 | 适合 |
|---|---|
| **命令行 / 终端** `musiccil` | 听指定歌曲、要推荐歌单、在脚本和 AI agent 里调用 |
| **图形界面** `gui/` 里的独立 exe | 手动搜歌、翻列表、慢慢攒歌单、一键开播 |

图形界面不重复实现播放：它只负责"找歌、组歌单"，点播放时把歌单交给终端播放器。
封面主题色、歌词、系统媒体键这些能力天然一致，不用维护两套。

## 安装

需要 Python 3.9+、[mpv](https://mpv.io/)（音频后端）、Pillow。

```bash
pip install -e .
```

mpv 会自动在 PATH 与常见安装位置查找；装在别处就指一下：

```bash
set MUSICCIL_MPV=D:\tools\mpv\mpv.exe
```

### 配置接口密钥（必须）

曲库数据来自聚合接口，按次计配额，需要你自己的密钥。
**本仓库不含任何密钥**——硬编码在公开仓库里等于把接口配额送人。

密钥从本项目的 **musiccil API 调用站**免费领取：打开 <https://muscil.geekdom.top>，注册一个账号，
登录后在「控制台 → 我的密钥」里就能看到自己的密钥。第一次用播放器时它会自己问你：

```bat
musiccil --setup
```

把密钥粘进去，它会校验一次（**不扣配额**）然后存到 `%USERPROFILE%\.musiccil\key`，
以后所有命令都自动用它，不用再带参数。也可以一次性指定、或走环境变量：

```bat
musiccil --setup --key 你的密钥      # 非交互，Agent 可以代你保存
musiccil --key 你的密钥 "稻香"        # 只用这一次，不落盘
set MUSICCIL_API_KEY=你的密钥        # 当前窗口有效
```

没配置时不会静默失败，会直接提示怎么做。想看自己用了多少配额，去调用站的「控制台 → 用量统计」。

## 用法

什么都能直接喂进去：歌名、`平台:ID`、本地文件、目录、m3u、音频直链、歌单、排行榜、JSON 歌单。

```bash
musiccil "加州梦游" -l 5                # 搜索并依次播放
musiccil qq:001I6gzS3LufWy              # 平台:歌曲ID
musiccil "D:\Music\夜曲.flac"           # 本地文件
musiccil "D:\Music"                     # 整个目录
musiccil --list 149553                  # 网易云歌单
musiccil --toplist 3778678              # 排行榜
musiccil --user 123456 --pick 0         # 某用户收藏的第 1 个歌单
musiccil --file night.json              # 播放 JSON 歌单
musiccil "关键词" --search --json-out   # 只搜索，输出 JSON
```

### 三条"一步到位"的命令

从搜索到开窗播放只要一次调用，这是实测最省时的路径：

```bash
musiccil "A Rusty Dream" --artist DOUDOU --book song.json          # 指定歌曲
musiccil --mix mix.json "深夜 city pop 氛围" --mix-count 8          # 推荐歌单
musiccil --mix mix.json "DOUDOU 独立民谣" --seed "A Rusty Dream" --artist DOUDOU
                                                                   # 想听某首 + 再推荐几首
```

`--mix` 会自动去重、跳过 live/remix/伴奏版、限制同歌手数量，挑不满时自动翻页补足，
再并发解析音频/封面/歌词（10 首约 0.3 秒）。`--seed` 那首排第一位，其余自动补推荐。

`musiccil` 这个命令的脚本目录常常不在 PATH 里（Windows 尤其如此），
此时一律用 `python -m musiccil ...`——装好后在任何目录都能这样调用。

### 按键

`SPC` 播放/暂停 · `←/→` 快退快进 5s · `↑/↓` 音量 · `M` 静音 ·
`N/P` 上/下一首 · `H` 红心 · `S` 播放模式 · `L` 歌词 · `T` 列表 · `R` 主题 · `Q` 退出

### 换曲时的过渡

换歌时**配色和封面都会在 0.9 秒内渐变过去**（不是硬切），切歌/快进快退另有一次
0.22 秒的音频淡入淡出，声音不会被突然切断。三个时长都能调：

```bash
musiccil --theme-fade 1.6 "稻香"   # 配色/封面过渡，0 = 不过渡
musiccil --audio-fade 0.5 "稻香"   # 音频淡入淡出，0 = 直接切
musiccil --spin 8 "稻香"           # 唱片转速（度/秒），默认 15 约 24 秒一圈
```

## 图形界面（C++ / Win32）

原生 Windows 窗口程序，用 MinGW 一条命令编译，**不需要 Qt / wxWidgets / CMake**。

![界面](docs/images/gui.png)

```bat
cd gui
build.bat                          :: 产出 gui\build\musiccil-gui.exe
build\musiccil-gui.exe
```

- **搜索**：关键词 + 平台（网易云/QQ/酷狗/酷我/咪咕/千千），回车即搜；
  已加入歌单的条目会打勾，避免重复添加。
- **组歌单**：双击加入、全部加入、移出、上移/下移、清空。
- **一键播放**：自动保存歌单，并在独立终端窗口里拉起播放器。
- 歌单落在 `%LOCALAPPDATA%\musiccil-gui\playlist.json`，可以直接 `musiccil --file` 复用。

细节与实现坑见 [gui/README.md](gui/README.md)。

## 在 AI Agent 里用（Skill）

仓库自带技能包 `skills/musiccil/`，让 AI 能通过对话完成
「推荐歌 → 取音频/封面/歌词 → 交给播放器播放」：

```bash
cp -r skills/musiccil ~/.codex/skills/musiccil
```

技能里两条最重要的约束，都是实测踩出来的：

- **一次工具调用走完全程**。"搜一次 → 读结果 → 写歌单 → 再解析 → 再播放"这种拆步实测要 5 分钟，
  而命令本身只要 1 秒——时间几乎全耗在往返上。所以有 `--book` 和 `--mix` 两条一步到位的命令。
- **播放器必须开成独立窗口**。它是交互式 TUI，在 agent 会话里直接跑会进管道、用户什么都看不到；
  播放器检测到输出不是终端时会自己开窗，直接调用即可。

| 用户说 | Agent 执行 |
|---|---|
| "我想听 DOUDOU 的 A Rusty Dream" | `musiccil "A Rusty Dream" --artist DOUDOU --book %TEMP%\s.json` |
| "放点深夜 city pop" | `musiccil --mix %TEMP%\m.json "深夜 city pop 氛围" --mix-count 8` |
| "想听 X，再推荐几首" | `musiccil --mix %TEMP%\m.json "DOUDOU 独立民谣" --seed "X" --artist DOUDOU` |

技能开头会先确认密钥：没有就引导用户去 <https://muscil.geekdom.top> 领一把，
再用 `musiccil --setup --key <密钥>` 保存（Agent 可以代劳）。

接口字段、平台差异与已知坑：`skills/musiccil/references/api.md`、`references/cli.md`。

## 独立窗口运行

播放器是交互式界面，需要真正的终端。当它发现**看不到用户**时——标准输出被管道接管，
或虽然连着终端但窗口是隐藏的（agent 的 PTY 就是这样）——会自动新建一个终端窗口运行，
当前命令立刻返回并打印窗口进程号和按键提示。窗口标题会实时显示当前曲目。

```bash
musiccil "深夜 city pop" -l 10     # 在终端里就地播放；在管道/agent 里自动开窗
musiccil --file night.json         # 同上
musiccil --window ...              # 强制开新窗口
musiccil --no-window ...           # 强制就地运行（输出必须是真终端）
musiccil --window-size 50x46 ...   # 自定义窗口尺寸（默认竖屏 50x42）
```

窗口**默认竖屏 50×42**（约 515×848 像素），唱片约占整屏高的三分之一，留白舒展。
Windows 上优先用 `wt --size` 开窗，这样窗口本身真的是竖的；没有 Windows Terminal 时
回退到新建控制台并由播放器自己调整尺寸。

注意**不要**对播放器做输出重定向（`> log`、`| tee` 等）：Windows 上新控制台的 tty
只有在不重定向 stdout 时才成立，重定向后窗口里画不出界面。

## 系统媒体控制（Windows）

播放时曲目会发布到系统媒体通知：任务栏媒体面板能看到曲名、歌手、专辑、封面和进度，
键盘上的播放/暂停、上一首/下一首也能直接控制播放器。默认开启，`--no-media-controls` 可关。
依赖 `winsdk`（`pip install -e ".[media]"`），没装不影响播放，只是没有系统媒体控制。

## 设计要点

- **主题跟随封面**：量化封面色，按饱和度/明度/占比挑出主色，据此推导背景、顶栏、强调色、
  按钮底色与黑胶凹槽色，保证暗色底、可读文字和可见顶栏。
- **换曲配色渐变**：切歌时新主题不直接赋给界面（那会整屏"啪"地跳色），而是在 0.9 秒内
  从当前配色插值过去。鲜艳色按 HSV **最短色相弧**旋转（蓝→红走紫那边，中途不掉饱和度），
  暗色背景走 RGB 直插以免中途泛出怪彩色；进度用 smoothstep 缓入缓出。
- **换曲封面渐变**：封面像素画同样交叉淡入——上一首的网格和当前曲目的网格按同一进度插值，
  新曲没有封面时淡出成主题色而不是突然消失。过渡帧量化到 24 档并缓存，
  否则每帧都生成新网格会让旋转缓存全部失效。
- **像素封面旋转**：用半 block（`▀`）让**一个字符刚好对应一个封面像素**，封面缩成约
  20×20 的像素画放进唱片区，按最近邻旋转并缓存有限角度，唱针随播放/暂停起落。
  缩小用 **BOX 重采样 + 约 22 色量化（关闭抖动）**，边缘硬、色块干净，比 LANCZOS 明显清晰。
- **旋转同步**：黑胶高光用 `sin(ang + ...)`（一圈一次），与中心封面同一转速；
  用 `sin(2*ang)` 会变成两个对称高光，看起来外圈在以两倍速转。
- **转速**：默认 `SPIN_PER_SEC = 15`（24 秒一圈），可用 `--spin` 覆盖。角度档位 720 档、
  按 0.5° 量化缓存：早期量化到 1° 时，30fps 下每帧只推进 0.5°，有一半的帧原地不动，
  慢速下看起来一顿一顿。
- **切歌音频过渡**：用 mpv 的 `volume-gain`（独立增益层，dB）做淡出→切换→淡入，
  **不动用户设的音量**，界面音量条也不会跟着抖。不能阻塞界面：按下先静音，主循环按帧推进，
  淡出走完才真正切。连按下一首时逻辑位置立刻更新、只推迟"加载音频"那一步，
  否则第二下会算出同一个目标、两下只走一首。
- **退出时连带收掉 mpv**：正常退出走 `quit()`，但用户直接关窗口或在任务管理器里结束进程时，
  清理代码根本不会执行，mpv 会变成孤儿继续放歌。为此把 mpv 挂进一个设了
  `KILL_ON_JOB_CLOSE` 的 Windows **Job Object**——句柄随进程结束由内核关闭，系统就会连它一起收掉。
- **系统媒体控制**：用 winsdk 的 `MediaPlayer` 借一条 SMTC 通道发布曲名/歌手/专辑/封面/进度，
  并接收系统媒体键。两个坑：按键回调靠 Windows 消息队列派发，主循环必须周期性泵消息；
  回调参数是 WinRT 枚举对象，得读 `.name`（`str()` 只会给出 `"0"` 这种数字）。
  另外要让 mpv 关掉它自带的媒体会话，否则两个会话会抢媒体键。
- **界面严格定宽定高**：输出行数与宽度始终等于终端尺寸，否则终端会滚动或错位；
  中英日韩混排按 East Asian Width 计算列宽。
- **播放与界面分离**：mpv 在后台通过命名管道 IPC 接收指令，界面只读状态、自己绘制，
  所以换歌、跳转、音量都不会卡住界面。

## 已知限制

- 平台版权限制会让部分曲目取不到音频直链（QQ/酷我/千千较明显），播放器会自动跳过并在启动时提示；
  想要稳定播放建议优先用网易云（`wy`）或酷狗（`kg`）。
- 接口是第三方聚合服务，有固定包量配额，且返回的音频/封面地址有时效，不适合长期缓存。
- 接口对**多个词的关键词**容易返回"获取失败"，播放器会自动逐级丢词重试。
- 终端需支持真彩色（24-bit）；Windows Terminal、iTerm2、modern Linux 终端均可。
