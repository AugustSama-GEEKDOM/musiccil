# musiccil 命令行与歌单格式

## 用法

```
python -m musiccil [query ...] [选项]
```

用 `python -m musiccil` 而不是裸 `musiccil`：console script 的目录常常不在 PATH 里。

`query` 可以是搜索关键词、文件路径、目录、m3u、`平台:ID`、音频直链，或 JSON 字符串。
多来源优先级：`--list` / `--toplist` / `--user` > `query`。

## 选项

| 选项 | 说明 |
|---|---|
| `-p, --platform` | 平台：`wy`/`qq`/`kw`/`kg`/`mg`/`qi`，默认 `wy` |
| `-l, --limit` | 搜索数量，默认 10 |
| `--page` | 搜索页码，默认 1 |
| `--list ID` | 播放歌单（网易/QQ/酷我/酷狗/明月浩空） |
| `--toplist ID` | 播放排行榜（仅 wy/qq/kw） |
| `--user UID` | 取该用户的歌单，配合 `--pick N` 选择第几个 |
| `--file PATH\|JSON` | 直接给 JSON 曲目，可重复 |
| `--stdin-json` | 从标准输入读 JSON 曲目 |
| `--search` | 只搜索不播放 |
| `--json-out` | 结果输出为 JSON（隐含 `--search`） |
| `--playlist-out PATH` | 把结果写成 JSON 歌单文件 |
| `--no-resolve` | 不预取音频/封面/歌词，更快更省配额 |
| `--brief` | 只取筛选必需字段（id/type/name/artist/album），跳过逐首详情 |
| `--compact-json` | 输出 JSON 时省略空字段与 extra |
| `--book PATH` | 一步到位：搜索→挑原唱→解析资源→写歌单→开窗播放 |
| `--mix PATH` | 一步到位（推荐歌单）：一次搜索→自动去重去 live/remix→并发解析→写歌单→开窗播放 |
| `--mix-count N` | 配合 `--mix`，最终收录几首（默认 8） |
| `--per-artist N` | 配合 `--mix`，同一歌手最多几首（默认 2，0 为不限） |
| `--artist NAME` | 配合 `--book`，指定歌手以选对原唱（强烈建议带上） |
| `--book-count N` | 配合 `--book`，取前 N 首（默认 1） |
| `--no-play` | 配合 `--book` / `--mix`，只生成歌单不开窗 |
| `--offline` | 只用本地缓存的封面 |
| `--volume N` | 初始音量 0–100，默认 80 |
| `--favorites PATH` | 红心 ID 列表文件，每行一个 |
| `--key` | 接口密钥，默认取 `MUSICCIL_API_KEY` → `%USERPROFILE%\.musiccil\key` |
| `--setup` | 配置密钥：带 `--key` 时校验后保存（非交互，Agent 可用）；不带时提示用户粘贴 |
| `--no-setup` | 没密钥时不要弹交互引导，直接报错退出（脚本/CI 用） |
| `--width N` | 强制面板宽度 |
| `--render-once` | 只渲染一帧后退出 |
| `--window` | 在独立终端窗口里打开播放器 |
| `--no-window` | 强制在当前终端就地运行，不另开窗口 |
| `--window-size COLSxROWS` | 独立窗口的字符尺寸，默认竖屏 `70x56` |
| `--spin DEG_PER_SEC` | 唱片转速（度/秒），默认 `15`（约 24 秒一圈），调大转得更快 |
| `--theme-fade SECONDS` | 换曲时主题配色的过渡时长（秒），默认 `0.9`；`0` 为直接换色不过渡 |
| `--no-media-controls` | 不注册系统媒体通知（Windows 任务栏媒体面板与键盘媒体键） |
| `--audio-fade SECONDS` | 切歌/快进快退的音频淡入淡出时长，默认 `0.22`；`0` 为直接切换 |
| `--no-audio` | 只渲染界面不发声 |

## 独立窗口

播放器是交互式 TUI，需要真实终端。当输出不是终端（agent、脚本、管道调用）时，
默认会自动新建一个终端窗口运行，父进程立刻返回并打印窗口进程号与按键提示。

**默认竖屏 70×56**（约 780×1240 像素）。面板宽度跟随窗口宽度（最大 78 列）。
唱片刻意不占满：限制在唱片区高度的 70%、面板宽度的 70%，实测约占整屏高 35%，
再放大会显得头重脚轻。可用 `--window-size 列x行` 或环境变量
`MUSICCIL_WINDOW_SIZE=列,行` 覆盖。

实现要点（改这块代码时别踩）：

- **让窗口本身变竖只能靠 `wt --size 列,行`**：`CREATE_NEW_CONSOLE` 配控制台缓冲区/窗口
  API 只改 conpty 的网格，Windows Terminal 的窗口尺寸不跟着变，仍然是横的。
  所以优先走 `wt -w -1 --size C,R cmd /c ...`；找不到 `wt.exe` 时才回退到
  `CREATE_NEW_CONSOLE`，并由子进程用 `apply_console_size()` 自己调窗口
  （此时父进程置 `MUSICCIL_APPLY_SIZE=1`）。
- 回退路径上调尺寸的顺序必须是「先把窗口缩到最小 → 扩缓冲区 → 再把窗口撑到目标大小」，
  反过来会因为窗口装不下缓冲区而失败。
- `CREATE_NEW_CONSOLE` 会给子进程分配新控制台，此时它的 stdin/stdout/stderr
  都是真正的 tty，界面才能画出来。
- **不能**给该子进程传 `stdout=`/`stderr=` 重定向，否则新控制台里拿到的是管道，
  `isatty()` 为 False，界面画不出来。
- 子进程通过环境变量 `MUSICCIL_IN_WINDOW=1` 知道自己已在窗口里，避免递归开窗；
  通过 `MUSICCIL_TEMP_PLAYLIST` 拿到父进程写好的临时歌单，读后即删。

## 像素封面清晰度

唱片中心是封面缩成的像素画，清晰度由两处决定，改的时候别退回旧写法：

- **用 `Image.BOX` 而不是 `LANCZOS`**：LANCZOS 带负瓣，在几十像素的格子上会振铃、
  发糊；BOX 是区域平均，边缘更硬、色块更整。
- **量化到约 22 色且必须关闭抖动**：把渐变压成干净色块，辨识度反而更高；
  开了 dither 会给像素画撒噪点。颜色数太少会发灰，太多又会带回渐变噪声。
- **一个字符必须刚好对应一个封面像素**：居中的偏移量常常正好是 ±0.5，如果
  用 `int(round(x - ox))`，Python 的银行家舍入会把相邻两列映到同一个像素，
  等于把每个像素横向拉宽成 2 格（实测 38 个字符列只用到 19 个像素列），
  看起来就是"几个字符一个大色块"。必须用 `math.floor` 做 1:1 映射。
- 封面边长与唱片标签圆的比例 `LABEL_RATIO` 必须两边共用。标签圆用 A 比例、
  封面网格按 B 比例算，旋转采样会落到网格外，中心就会糊出一圈杂色。
- **黑胶高光只能是一圈一次**：`sheen` 用 `sin(2*ang)` 会得到两个对称高光，
  看上去外圈在以两倍速转、和内圈封面不同步；用 `sin(ang + dist*0.22)` 保证
  外圈亮度随角度以 360° 为周期，与封面同一个转速。

## JSON 歌单格式

数组或 `{"tracks": [...]}` 都接受，字段与下面的 `Track` 一致，未知字段会被保留在 `extra` 里：

```json
[
  {
    "id": "1474392057",
    "type": "wy",
    "name": "加州梦游",
    "artist": "闫泽欢/于梓贝",
    "album": "加州梦游",
    "url": "https://...mp3",
    "pic": "https://...jpg",
    "lrc": "[00:00.00] 作词 : ...",
    "duration": 266.9
  }
]
```

- `id` + `type` 是回查详情的依据；`url` / `pic` / `lrc` 留空时播放器会自动补全。
- 只想指定要播哪几首时，最省事的是只写 `id` 和 `type`：
  `[{"id": "1474392057", "type": "wy"}, {"id": "001I6gzS3LufWy", "type": "qq"}]`
- 本地文件用 `"url": "D:/Music/a.flac"`、`"type": ""` 即可。

## 快路径与慢路径

命令本身的耗时：

| 操作 | 实测 |
|---|---|
| 搜索 1 首（`--no-resolve`） | 0.5 s |
| 搜索 15 首 `--brief --compact-json` | 0.3 s / 1.7 千字符 |
| 搜索 15 首（默认，含歌词） | 3.5 s / 2.7 万字符 |
| 解析 10 首音频+封面+歌词（并发） | 0.3 s |
| `--book` 搜+挑+解析+开窗 | 约 1 s |
| `--mix` 搜+挑+并发解析+写歌单+开窗 | 约 1 s |

所以：**指定歌曲用 `--book`、要推荐歌单用 `--mix`**，不要把流程拆成多轮往返。
模型侧一次"搜→读→写→播"的往返实测要 5 分钟，几乎全是等待时间。

### --mix 的自动挑歌规则

`api.pick_mix` 从一次搜索结果里直接挑出可播歌单，不需要模型读候选：

1. 同一首歌只留一条——判据是「歌名 + 歌手集合」，因为平台既会把一首歌重复列成多条
   （只有 ID 不同），也会把同一首歌的歌手顺序写反（`李玟/周杰伦` 与 `周杰伦/李玟`）；
   拼歌手字符串去重会漏掉后者，歌单里就出现重复条目。
2. 同一歌手默认最多 2 首（`--per-artist` 可调）；
3. 没有明确要求时跳过 `live/演唱会/remix/伴奏/cover/翻唱` 等非原版；
4. 其余按平台返回顺序保留，凑满 `--mix-count` 为止。

规则是**逐级放宽**的，因为按风格搜索时整页可能都是同一位歌手的作品：
先按严格规则挑；凑不满就放开同歌手限制（宁可多给几首同歌手的，也不只给两三首）；
只有当原版一首都没挑到时，才回退使用变体版本。为了挑掉变体后仍能凑满数量，
会按 `2×count` 的量搜索候选；仍然不够就自动再翻一页（`--page` 的下一页），
所以歌单不会因为前几条正好是重复条目而缩水。

## 并发

`MusicApi.resolve` 和 `best_across_platforms` 都用线程池并发发请求（最多 8 路），
这是 1 秒级响应的关键：

- `resolve` 串行解析 10 首要 4.3 s，并发后 0.3 s；返回顺序仍与入参一致。
- `best_across_platforms` 串行按 `wy→kg→kw→qq` 试探最坏 3.9 s，并发后 0.8 s。
  指定平台在分数相同时有轻微优先，不会因为并发而冷落用户点名的平台。

## 原唱匹配

`--book --artist X` 的匹配规则（`api.best_across_platforms`）：

- 歌手必须**精确相等**，或作为**独立的合作歌手名**出现。不用子串匹配，
  否则「周杰伦./街道办GDC」这种联名翻唱会被当成原唱。
- 歌手对上了还要求歌名对得上，避免"歌手命中但拿错歌"。
- 当前平台找不到合格原唱时，按 `wy → kg → kw → qq` 自动换平台。
  实测周杰伦、陈奕迅等原版常在网易云缺席，而酷狗/酷我有收录。

| 变量 | 用途 |
|---|---|
| `MUSICCIL_API_KEY` | 覆盖接口密钥（优先级高于本地密钥文件） |
| `MUSICCIL_API_BASE` | 覆盖接口基址，默认 `https://muscil.geekdom.top/open/music/`。自建一套或本地调试时才需要 |
| `MUSICCIL_MPV` | 指定 mpv 可执行文件路径 |
| `MUSICCIL_WINDOW_SIZE` | 窗口尺寸（`列,行`），等价于 `--window-size` |

## 音频过渡

切歌、上一首/下一首、快进快退、以及"回到开头"都会做一次 0.22 秒的淡出 → 切换 → 淡入，
声音不会被硬切出"啪"的一声。用 `--audio-fade` 调（0 为直接切换）。

实现要点（改这块时别踩）：

- 用 mpv 的 `volume-gain`（dB）而不是 `volume`：前者是独立增益层，
  改它不会污染用户设的音量、界面音量条也不会抖。`-60` 近似静音。
- **不能阻塞界面**：按下后先静音，主循环按帧推进，淡出走完才真正切歌。
- 连按下一首：逻辑位置（`index`）必须**立刻**更新，只推迟"加载音频"那一步。
  否则第二下会算出同一个目标，连按两下只走一首。

## 退出行为

关掉播放器窗口/进程时，mpv 会被一起收掉，不会留在后台继续放歌。
实现方式是 Windows Job Object + `KILL_ON_JOB_CLOSE`：正常退出走 `quit()`，
但直接关窗口、任务管理器结束进程这些路径根本轮不到 Python 清理代码执行，
只有把 mpv 挂进 job 才能靠内核兜底。

## 系统媒体控制（Windows）

播放时会把当前曲目发布到系统媒体通知（任务栏媒体面板 / 音量键浮层）：
**曲名、歌手、专辑、封面、播放进度**都在，键盘上的播放/暂停、上一首/下一首、
快进快退可以直接控制播放器。

- 关掉：`--no-media-controls`。`--no-audio` 时自动关闭（没有真实播放源，发了也是误导）。
- 依赖 `winsdk`（`pip install -e ".[media]"`）。**没装也能正常播放**，只是没有系统媒体控制。
- 实现要点（改这块代码时别踩）：
  - 用 winsdk 的 `MediaPlayer` 借一条 SMTC 通道，**不能让它真的播音频**，否则会和 mpv 抢声音；
    音频始终由 mpv 播放。
  - 按键回调靠 Windows 消息队列派发，主循环必须周期性 `PeekMessage` 泵消息，
    只 `time.sleep` 是收不到任何按键的。
  - 回调参数是 WinRT 枚举对象，动作名在 `.name`（`PLAY`/`NEXT`…）；`str()` 只会给出 `"0"` 这种
    数字，用它匹配会全部静默失效。
  - 必须给 mpv 传 `--no-media-controls --input-media-keys=no`：mpv 自己也会注册一个
    只有标题、没有歌手/封面的会话，两个会话并存会抢媒体键。
  - 会话状态枚举和设置用的枚举**不是同一套**：会话端 `4` 是 PLAYING、`5` 是 PAUSED。

## 按键

`SPC` 播放/暂停 · `←/→` 快退快进 5s · `↑/↓` 音量 · `M` 静音 · `N/P` 上/下一首 ·
`H` 红心 · `S` 播放模式（顺序/随机/单曲） · `L` 歌词页 · `T` 列表页 · `R` 主题 · `Q` 退出

## 退出码

- `0` 正常（含 `--search` 有结果）
- `1` `--search`/`--json-out` 没有结果
- `2` 启动或解析失败
